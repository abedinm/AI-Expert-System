# 1. ALPHA-BETA PRUNING

Two players. **MAX** wants the highest value, **MIN** the lowest. Alpha-beta returns the
**exact same answer as minimax** but skips branches that cannot possibly change it.

## The two values
- **α (alpha)** — best value **MAX** can guarantee so far. Starts **−∞**. Only MAX updates it.
- **β (beta)** — best value **MIN** can guarantee so far. Starts **+∞**. Only MIN updates it.

## The three rules
1. Search **left to right, depth first**
2. Values pass **child → parent**; α/β pass **parent → child**
3. **Prune when α ≥ β**

## Worked example
MAX root, three MIN children, leaves `[3,12,8] [2,4,6] [14,5,2]`

- MIN₁ → 3. Root α = 3
- MIN₂ sees 2. Since 2 ≤ α(3) → **prune 4 and 6**
- MIN₃ → 2
- Root = max(3, 2, 2) = **3**, examined **7 of 9** leaves

## Move ordering — the key insight
Same nine leaves, reordered as `[6,6,9] [4,5,3] [5,6,7]`:
α reaches 6 immediately, so **4 leaves get pruned instead of 2** — only 5 of 9 examined.

**Ordering changes how much you save. It never changes the answer.**

## Complexity
| | |
|---|---|
| Plain minimax | O(bᵐ) |
| Alpha-beta, worst ordering | O(bᵐ) — no saving |
| Alpha-beta, **perfect ordering** | **O(b^(m/2))** — search roughly twice as deep |

# 2. GENETIC ALGORITHM

**Definition to memorise:** a GA is a variant of **stochastic beam search** in which successors
are generated by **combining two parent states** rather than modifying a single state.

## The cycle
```
Initialize population → Evaluate fitness
        ↓
   1. SELECTION      pick parents by fitness
   2. CROSSOVER      combine two parents
   3. MUTATION       small random change, low probability
   4. SURVIVAL       accept into the new population
        ↓
   repeat until the termination condition
```

## Encoding — three types
| Type | Example | Used for |
|---|---|---|
| **Binary** | `10110` | numeric optimisation |
| **Value** | `1.23 5.67` | real numbers, weights |
| **Permutation** | `1 5 3 2 6 4` | ordering problems (TSP, scheduling) |

## Selection
**Roulette Wheel (fitness-proportionate)** — `P(i) = fitnessᵢ ÷ Σ fitness`
Build **cumulative bins**, generate a random number, see which bin it lands in.

**Best Selection** — simply take the **top N by fitness**. No bins, no randomness.

Others: **Tournament** (pick k, fittest wins) · **Rank** (select by rank, stops a super-individual
dominating) · **Elitism** (best individuals copied through untouched) · **SUS**.

⚠️ Selection pressure too high → premature convergence. Too low → near-random search.

## Crossover — six types
| Type | How |
|---|---|
| **One-point** | one cut, swap the tails |
| **Two-point** | two cuts, swap the middle |
| **Uniform** | each gene from P1 or P2 by a mask |
| **Arithmetic** | an arithmetic op, e.g. `α·P1 + (1−α)·P2` |
| **Heuristic** | uses fitness to extrapolate from the better parent |
| **Three-parent** | see the rule below |

**Three-parent rule:** for each bit — **if P1 == P2 take P1, else take P3.**

**One-point worked:** `P1=000011110011`, `P2=101010101010`, point 4
```
C1 = 0000|10101010 = 000010101010
C2 = 1010|11110011 = 101011110011
```

## Mutation
Low probability (~1%). **Flip-bit** for binary. For **permutation** encoding you must **swap**
two positions — flipping would break the permutation.

## The numerical example: maximise f(x) = x²/2 − 3x, x ∈ [0,31], 5-bit
2⁵ = 32, so five bits cover 0–31 exactly.

| Chromosome | x | f(x) | Used | Probability |
|---|---|---|---|---|
| 10010 | 18 | 108 | 108 | 0.211 |
| 10011 | 19 | 123.5 | 123.5 | 0.242 |
| 10111 | 23 | 195.5 | 195.5 | 0.383 |
| 01110 | 14 | 56 | 56 | 0.110 |
| 00101 | 5 | **−2.5** | **0** ⚠️ | 0 |
| 01011 | 11 | 27.5 | 27.5 | 0.054 |
| | | | **Total 510.5** | |

⚠️ **The trap: negative fitness is clamped to 0 and gets no slice of the wheel.**

Selection with randoms 0.54, 0.88, 0.45, 0.20 → chromosomes **3, 4, 2, 1**.
Best offspring `11110` → x = 30 → **f = 360**.

# 3. 8-QUEENS PROBLEM

## Encoding
**One queen per column.** Chromosome = n digits; digit *i* = the **row** of the queen in column *i*.
The column constraint is built in, so two queens can never share a column.

## Fitness
**Fitness = number of NON-attacking pairs.**
```
maximum pairs = n(n−1)/2
```
| n | Max fitness |
|---|---|
| 8 | **28** |
| 6 | **15** |
| 4 | 6 |

**Two queens attack if:** same row (`row[i] == row[j]`) **OR** same diagonal
(`|row[i] − row[j]| == |col[i] − col[j]|`).

## The counting method
Go column by column, comparing **only rightward** (never double-count).
Column 1 makes 7 comparisons, column 2 makes 6 … column 8 makes 0 → 7+6+5+4+3+2+1 = **28** ✓

**Worked — `24748552`:**
```
Attacked:      1  1  1  0  0  1  0  0   → 4
Non-attacked:  6  5  4  4  3  1  1  0   → 24
```
**Fitness = 28 − 4 = 24**

*Sanity check: the two rows must sum to 28. If they don't, you miscounted.*

## The four standard states
| Chromosome | Attacks | Fitness | Roulette share |
|---|---|---|---|
| 24748552 | 4 | **24** | 24/78 = 31% |
| 32752411 | 5 | **23** | 29% |
| 24415124 | 8 | **20** | 26% |
| 32543213 | 17 | **11** | 14% |
| | | **Total 78** | |

## The shortcut trick (faster than drawing the board)
For each digit, scan **rightward** with three checks:
1. **Duplicate** — same digit to the right → same row
2. **Count up** — +1, +2, +3 … matches a digit → diagonal
3. **Count down** — −1, −2, −3 … matches a digit → diagonal

**Demo on `2 4 7 4 8 5 5 2`, digit 3 = `7`:** count down moving right → 6, 5, 4, 3, **2** — and
the digit there *is* `2` → **diagonal attack (col 3 ↔ col 8)**.

⚠️ **Watch the sign flip:** hill climbing **minimises attacks** (h → 0);
GA **maximises non-attacking pairs** (fitness → 28). Same problem, inverted measure.

# 4. CONSTRAINT SATISFACTION (CSP)

## The three components
| Component | Meaning | Map-colouring example |
|---|---|---|
| **Variables** | what gets assigned | WA, NT, SA, Q, NSW, V, T |
| **Domains** | allowed values | {Red, Green, Blue} |
| **Constraints** | what's forbidden | adjacent regions must differ |

A **solution** = a complete, consistent assignment.

## Constraint graph
One node per variable, an edge between any two that share a constraint.
Australia's degrees:

| Variable | Neighbours | Degree |
|---|---|---|
| **SA** | WA, NT, Q, NSW, V | **5** ← most constrained |
| NT, Q, NSW | | 3 each |
| WA, V | | 2 each |
| T | — | 0 (island) |

## Forward checking
After each assignment, **delete that value from every neighbour's domain**.
**Empty domain ⇒ backtrack immediately.**

After `WA = Red`:
```
NT {G,B}   SA {G,B}   Q {R,G,B}   NSW {R,G,B}   V {R,G,B}   T {R,G,B}
```
After `WA = Red, NT = Green`:
```
SA {B}     Q {R,B}    NSW {R,G,B}   V {R,G,B}   T {R,G,B}
```

## The two heuristics — the classic exam trap
**MRV (Minimum Remaining Values)** — "most constrained variable"
> Pick the variable with the **fewest values left**. Fails fast, prunes early.
> Above → **SA** (domain size 1).

**Degree heuristic** — "most constraining variable"
> Pick the variable in the **most constraints on unassigned variables**.
> Used to **break MRV ties** — typically at the very start when all domains are full.
> All size 3 → tie → degree picks **SA** (5 neighbours).

⚠️ **MRV counts values left. Degree counts neighbours.**

# 5. BAYESIAN NETWORKS

A directed acyclic graph. Each node is a variable, each edge means "directly depends on".
Every node stores **P(node | its parents)**.

## The five rules
1. **Complement:** `P(¬X) = 1 − P(X)`
2. **Chain rule:** full joint = **∏ P(node | parents)** — follow the arrows downward
3. **Root nodes** just use their prior
4. **Marginalise:** a variable not fixed by the question → **sum over all its values**
5. **Normalise:** `P(X | e) = P(X, e) ÷ P(e)`

## Network A — burglary / earthquake / alarm
```
  Burglary      Earthquake
       \           /
          Alarm
         /     \
  JohnCalls  MaryCalls
```
P(B)=0.001 · P(E)=0.002
P(A|B,E)=0.95 · P(A|B,¬E)=0.94 · P(A|¬B,E)=0.29 · P(A|¬B,¬E)=0.001
P(J|A)=0.90 · P(J|¬A)=0.05 · P(M|A)=0.70 · P(M|¬A)=0.01

**Worked:**
```
P(j, m, a, ¬b, ¬e) = P(¬b)·P(¬e)·P(a|¬b,¬e)·P(j|a)·P(m|a)
                   = 0.999 × 0.998 × 0.001 × 0.90 × 0.70
                   = 0.000628
```
*(Verified: the full joint over all 32 combinations sums to exactly 1, and
P(B | j, m) = 0.284 — the textbook value.)*

## Network B — cloudy / sprinkler / rain / wet grass
```
        Cloudy
       /      \
 Sprinkler    Rain
       \      /
      WetGrass
```
P(C)=0.5 · P(S|C)=0.10, P(S|¬C)=0.50 · P(R|C)=0.80, P(R|¬C)=0.20
P(W|S,R)=0.99 · P(W|S,¬R)=0.90 · P(W|¬S,R)=0.90 · P(W|¬S,¬R)=0.00

Useful verified values: **P(w) = 0.6471** · **P(c | w) = 0.5758** · **P(r) = 0.50**

# SUPPORTING MATERIAL

## Local search (Lecture 4)
Path is irrelevant, only the final state matters. Constant memory.
Landscape traps: **local maxima · plateaux · ridges**.

- **Hill climbing** variants: steepest-ascent · stochastic · first-choice · **random-restart**
- **Simulated annealing:** accept a bad move if `random < e^(ΔE/T)`; uphill always accepted; T falls over time
- **Local beam search:** keeps *k* states. **Stochastic beam search is GA's direct ancestor.**

8-queens performance: plain hill climbing **~14%**, with sideways moves **~94%**,
random-restart expected restarts **1/p ≈ 7**.

## Agents (Lecture 2)
- **PEAS** = Performance, Environment, Actuators, Sensors
- Environment: observable · deterministic · episodic · static · discrete · single-agent
- Types: simple reflex → model-based → **goal-based** → utility-based → learning
- **Your own lab code is an example of each:** the water purification agent is **goal-based**
  (it tests against an explicit goal state); the vacuum agent is a **simple reflex** agent
  (it reacts only to the cell it currently occupies).

# SOLUTIONS

## Part A — Alpha-Beta

**A1 → value 6 · pruned 5 and 3 · examined 7 of 9**
MIN₁ = 5, α = 5. MIN₂ sees 4 ≤ 5 → prune the rest of that branch. MIN₃ = 6. Root = max(5,4,6) = **6**.

**A2 → value 6 · pruned 2 and 7 · examined 6 of 8**
MIN₁ = 3, α = 3. MIN₂ = 6, α = 6. MIN₃ sees 1 ≤ 6 → prune 2. MIN₄ sees 0 ≤ 6 → prune 7.

**A3 → value still 6, but 4 leaves pruned, only 5 of 9 examined**
MIN₁ = 6 sets α = 6 immediately, so MIN₂ (4) and MIN₃ (5) both cut out early.
**This is the lesson: ordering changes the saving, never the answer.**

**A4 → value 1 · pruned 9 · examined 5 of 6 · root updates β**
MAX₁ = 3, β = 3. MAX₂ sees 5 ≥ 3 → prune 9. MAX₃ = 1. Root = min(3,5,1) = **1**.

**A5** (a) **No, never** — identical to minimax. (b) **α ≥ β**. (c) **O(b^(m/2))** — about twice the depth.

## Part D — CSP

**D1 — degrees**
| Variable | Neighbours | Degree |
|---|---|---|
| **C** | A,B,D,E | **4** |
| B | A,C,D | 3 |
| D | B,C,E | 3 |
| A | B,C | 2 |
| E | C,D | 2 |

**D2 — after A = R**
```
B {G,B}    C {G,B}    D {R,G,B}    E {R,G,B}
```
B and C both have 2 → **MRV ties**. Degree breaks it: **C (4) beats B (3) → choose C.**
*This is precisely what the degree heuristic is for.*

**D3 — after A = R, B = G**
```
C {B}    D {R,B}    E {R,G,B}
```
**MRV picks C** (single value). C lost R from A and G from B.

**D4 — after A = R, B = G, D = R**
```
C {B}    E {G,B}
```
**Still viable** — no empty domain. Full solution: **A=R, B=G, C=B, D=R, E=G**.

**D5** (a) **MRV counts values left; degree counts neighbours.** MRV chooses the variable,
degree breaks ties. (b) The moment **any domain becomes empty**. (c) An island has no
constraints, so any value works — assign it last, it can never cause backtracking.
